★ 第一铁律：手机端优先

  • ✓
    主力设备＝荣耀 Magic5 Pro（手机端），平板 / 桌面次之。每次部署必须把手机端显示当作默认验收标准（详见下方"目标设备与显示参数"）。
  • ✓
    文字不挤兑、不折成多行：名称/打卡时间/按钮同行时用 flex 不 wrap，超长用 text-overflow:ellipsis 兜底；时间统一右对齐单列，绝不混进名称行被挤掉。
  • ✓
    点击区域适合拇指：按钮/勾选 ≥32px；行间距宽松，避免误触。
  • ✓
    文本框 / 显示区文字必须完整可见：输入与展示区域的滚动/换行要能容纳完整内容，不得被裁切或挤成多行错乱；风格简洁统一。卡片头部标签过多时主动拆成"标题一行 + 标签/操作一行"。

1 数据不丢失（最高优先级）

  • ✓
    任何改动不得清除用户已记录数据；用户数据存 localStorage，与 HTML 源码分离。
  • ✓
    新字段在 load()/migrate() 中默认补全（如 loop、actTaskDone），旧数据零迁移风险。
  • ✓
    编辑用深拷贝草稿，原记录仅在保存成功后被替换。

2 每日打卡模块

  • ✓
    子项默认每日循环（loop 缺省 true），无需逐一点确认；点循环键或删除即可取消。
  • ✓
    独立事项也可循环：无子项时事项右侧显示 🔁，编辑面板有"该事项每日循环"开关。
  • ✓
    有子项的事项默认展开（可自由收起）；子项区顶部统一标注"以下成员均为每日循环项"。
  • ✓
    dailyResetCheck 零点：循环项/子项保留待重勾，非循环（一次性）跨天移除。
  • ✓
    加新成员（如 F）不影响 A–E 历史；历史按"日期+成员"独立存档。

3 阴阳师模块

  • ✓
    周常每周一整体刷新（协同/百鬼/结界当期累计清空）。
  • ✓
    活动进度双线实时：⏱ 时间进度（按起止日期自动推导）+ ✅ 内容进度（按子项勾选占比），随时间/勾选实时更新。
  • ✓
    子任务完成改为活动级持久存储，跨天保留。
  • ✓
    活动卡片头部手机端防折行：标题一行、标签/操作一行。

4 工作台账 / 工作记录

  • ✓
    "工作待办"已改名工作台账；新增独立页工作记录。
  • ✓
    统计整合为模块内第 3 个聚合 Tab；图表横向柱/折线/环形 + 时间筛选，默认当月。
  • ✓
    已完成项可编辑/重开/归档，"归档已完成"保留数据、统计不吞。

5 换肤系统

  • ✓
    五分类约 48 色（中国传统色/日本传统色/莫兰迪色/轻亮色/复古色）+ 双色搭配(A主/B辅)。
  • ✓
    浅色 Fix：近白颜色保留辨识度；softColor 高亮色不冲白。
  • ✓
    皮肤 onclick 用单反斜杠 \' 转义（曾误报双反斜杠，真实文件本无 bug）。

6 数据显示规则（全站通用）

  • ✓
    所有数值最多保留小数点后两位，可四舍五入。
  • ✓
    显示本身带等号/赋值含义（如"≈X"或等于号语境）时，若做了四舍五入，可在数字前加 ≈ 表示估算。
  • ✓
    显示语境不含等号（进度条百分比、金额、计数等纯呈现）时，直接显示四舍五入后的结果即可，不必额外标注"估算"。

7 部署流程铁律

  • ✓
    目标地址固定 https://boomgari.github.io/，每次改动直接推原链接，各设备刷新即见。
  • ✓
    部署前必查隐藏 bug 与整体 UI：跑 node --check 全脚本语法校验；关键新函数用真实代码实跑场景验证；核对整体 UI 表现、确保文本框文字完整可见、风格简洁统一，力求落地后直接正常使用。
  • ✓
    大文件用 GitHub git refs→commit→tree 取线上 blob SHA 再 PUT，规避整文件下载的 IncompleteRead 中断。
  • ✓
    收到明确"部署"指令即在同一轮执行，不再二次确认（除非用户说"先给草图/等确认"）。
🔑 令牌策略：本机（公司电脑）使用临时 PAT；因公司机不挂永久令牌，用户会在到期前申请 30 日新令牌替换 gh_token.txt。注意——令牌失效且未换新时，自动上载清单/日志会失败，故到期前务必更换。
